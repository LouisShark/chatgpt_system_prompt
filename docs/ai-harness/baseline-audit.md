## 5. Existing CI Workflows

| Workflow | File | Trigger | Purpose |
|----------|------|---------|---------|
| Generate TOC | `.github/workflows/build-toc.yaml` | `push` to `main` | Runs `idxtool.py --toc`, commits TOC.md |
| Update token count | `.github/workflows/update-token-count.yml` | `push` to `main` (paths filter) | Runs `nanoclaw/repo-tokens@v1.2.0`, commits badge SVG |

Both workflows **commit directly to `main`** under a concurrency group `main-push`.
Changes to these files must not disrupt this concurrency group.

**Actions versions in use**:
- `actions/checkout@v3` (build-toc) and `@v4` (update-token-count)
- `actions/setup-python@v3` (build-toc) and `@v5` (update-token-count)
- `qwibitai/nanoclaw/repo-tokens@v1.2.0` (update-token-count) — pinned version ✓

## 10. Likely Scope-Creep Risks

| Risk | Rationale |
|------|-----------|
| New Python dependencies pulled in silently | Repository has only `GitPython`; any addition changes the surface area |
| CI workflows modified without documented reason | The two workflows are tightly coupled to `main`-push behaviour |
| `prompts/` directory treated as config | It is content, not configuration; tools must treat it read-only |
| Supermemory indexing prompt content | The prompt files contain GPT instructions that must never be auto-uploaded as memories |
| Scope creep in Claude Code instructions themselves | CLAUDE.md or `.claude/` commands that add autonomous behaviour not scoped to this repo |

---

## 11. Likely Memory-Authority Conflicts

| Conflict | Mitigation |
|----------|-----------|
| Supermemory recalling a stale architectural decision that was overruled in a later commit | Authority order in `memory-policy.md`; explicit superseded-by field required |
| Claude Code using a stored memory to override an explicit user instruction in the session | Memory-policy.md must state: memory never overrides current session instructions |
| Two memories with contradictory guidance about the same topic | Deletion procedure required; see `memory-policy.md` |
